# 2026-09-30：固定调用槽、共享截止与 protobuf 基线

本轮按 A 保留公开 `net::task<call_result>`，完成固定调用槽/流号索引、服务端长期 worker、每 context 共享精确截止堆、冷方法绑定、builder 与状态说明。
同线程闭环的多数配置改善，分配明显减少；跨进程存在回归，开放负载仍未全部满足错误率与发起迟到门槛，不能宣布完整性能验收通过。
生命周期与兼容说明见 [运行时升级](../../docs/runtime-upgrade.md)。

未插桩 Release，GCC 13.3/C++14、`-O3 -DNDEBUG`、epoll、系统帧分配器、单条回环 TCP、TCP_NODELAY；接收窗口 65536 B、64 streams。
net `7dff859`、co2 `a265e57`、protobuf 3.21.12，依赖未修改。同线程固定 CPU 2，跨进程客户端 CPU 2、服务端 CPU 4。
机器为 i7-13700KF、Linux 7.0.0-34，powersave/balance_performance、turbo 开启，未独占。
测量期间没有并行编译、测试或其它本项目基准。

旧库取自本轮开始的 `07a0eef`，二进制在运行时改动前冻结，并使用与新版相同的新增 protobuf 基准驱动。
`implementation.tar` 只包含旧库来源；新增驱动、proto 与 CMake 另存 `harness.tar`，原 Cache/compile_commands 在重建前保存。
每轮环境分别记录旧二进制/归档/构建配置、新二进制与源码哈希。不能将当前工作树当作旧二进制源码。
前后版本及配置隔轮反转执行；全部逐请求 CSV 的分类计数、时序和分位数均独立校验。
closed 之后比较脚本新增可选的 `--inflight` 过滤，默认矩阵未变；原脚本已保存并核对 已记录的哈希。基准 C++ 驱动在冻结前后保持相同来源。
64/4096 B 指编码后业务载荷；protobuf 单 bytes 字段分别含 62/4093 B 内容。
该共用驱动走兼容字符串 typed 入口，未测生成 Stub 的冷绑定收益。

同线程与跨进程各 24 组（bytes/protobuf × 64/4096 B × 1/8/64 在飞 × 0/50 ms 截止），每组 3 轮、预热 2000、正式 20000。
两种拓扑各 144 轮，全部零错误。短轮同线程 bytes64/n1/无截止的 p99 中位数曾由 4.782 升到 6.245 µs，原始结果完整保留。
因此专门延长单在飞的 8 组到各 5 轮、预热 5000、正式 100000；80 轮全部零错误。

24 组短轮中，同线程 64 B/n64/50 ms 的 bytes p99 为 80.907→57.147 µs，protobuf 为 95.619→71.255 µs。
全部配置的吞吐、CPU、分位数与有效性保存在快照中，不以这些例子替代完整矩阵。

跨进程的结果不全面改善：protobuf4KiB/n1/50 ms 三轮 p99 全部上升，配对变化 +0.5%/+6.4%/+12.3%，中位数 11.179→11.894 µs。
protobuf64/n1/50 ms 的配对中位数 +3.8%，protobuf4KiB/n1/无截止 +1.0%。这些回归尚未通过采样归因。
跨进程还有明显尾部波动，例如新版 bytes64/n64/50 ms 的三轮 p99 范围 47.778–1497.636 µs；不剔除这轮。

固定调用槽、开放寻址表、长期 worker 和共享 timer 消除了相应逐调用对象/表项/定时器/root 完成状态分配。
公开 task、读帧、用户 handler/typed adapter、StopState 和消息资源仍有分配，未实现零分配。
无网络 API 表示原型中，144 B 直接 awaiter 可放入当前 192 B co2 内联空间，包装分配为 A=1、B=0。
原型未实现完整 RPC 生命周期；其纳秒延迟不是网络收益证据，用户已选择 A。

开放负载另跑同线程每秒 300000 次、128 个驱动槽，8 组各 3 轮、正式 100000（约 0.33 秒计划区间）。
有效门槛为全部成功、无驱动丢弃、每次发起迟到 ≤100 µs。
旧版 17/24 轮、新版 18/24 轮有效；各自拒绝合计 71、65 次，没有超时、其它错误或驱动丢弃。
各轮最大发起迟到范围为旧版 18.057–198.247 µs、新版 19.088–187.218 µs。
这仍是短轮：不能覆盖此前 600000 请求的加长验收，也不能把无效轮的成功 p99 当成零错误负载结论。
本轮未重新对照裸 net，未证明 §13 的额外开销 ≤0.7 µs、截止成本 ≤20 ns 或多分片等目标。

正确性验证：普通 Debug 18/18；protobuf Debug、Release、ASan/UBSan/LSan 各 24/24；TSan 17/17，四种网络后端均运行。
回归覆盖代际与取消竞态、共享堆容量/重挂/退出、构造配额回滚、监听启动 OOM 排空、批量绑定 OOM/冲突回滚、builder 重试、
长错误说明含 NUL 的寿命与复制 OOM、说明/metadata 共存和生成符号遮蔽。
基准 CSV 校验器的 5 项边界测试通过。发行版 protobuf 二进制未插桩；TSan 排除全局 new 故障注入程序。
net 的 [冷定时器堆 OOM](../../docs/net-timer-oom.md) 仍无法由 RPC 捕获，常规测试通过不表示任意 OOM 可恢复。
