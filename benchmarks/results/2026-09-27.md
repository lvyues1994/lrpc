# 2026-09-27：单分片原始字节基线

已建立逐请求延迟基线；帧缓存降低了分配次数，但未稳定改善 p99，因此本轮不改变 RPC 运行库的默认配置。
这些结果只代表同进程、同线程、一条回环 TCP 的原始字节 Echo，尚未达到设计稿的完整性能验收。
后续 [P0 加长观察](2026-09-27-p0.md) 在每轮 600,000 次时发现调度迟到和拒绝；本报告的短轮开放负载通过记录不代表持续稳定达标。

环境为 i7-13700KF、Linux 7.0.0-34、GCC 13.3、C++14、`-O3 -DNDEBUG`、epoll、`TCP_NODELAY`，固定 CPU 2。
CPU 2 与 CPU 3 共享物理核，未独占机器；频率策略为 `powersave` / `balance_performance`，turbo 开启。
依赖为 net `7dff859`、co2 `a265e57`。连接、握手、首次方法定义与预热均排除；成功回复逐字节验证。

闭环及缓存对照共 30 种配置、每种 5 轮，每轮预热 5,000 次、正式 100,000 次，150 轮均零错误。
下表使用系统帧分配器、无截止，单位 µs；p99 是逐轮 p99 的中位数，方括号保留各轮范围。
raw 单在飞直接读写，多在飞使用固定长度 FIFO；公共驱动相同，raw 不提供 RPC 的准入、截止或取消语义。

64 B 单在飞的 p50 中位数为 net 3.250 µs、RPC 4.148 µs。两者分位数之差不是额外开销的分布，
不能据此宣称设计稿的 ≤ 0.7 µs 目标已经满足；本轮也未测 protobuf。

开放负载共 20 种配置、每种 3 轮，每轮预热 5,000 次、正式 30,000 次。发生器有 128 个槽，RPC stream 上限为 64。
有效轮要求全部请求成功、无发生器丢弃，且每次实际发起相对计划迟到不超过 100 µs；60 轮中 27 轮满足。
每秒 300,000 次、均匀发起的四组对照均为 3/3 轮有效，以下仍为逐轮分位数的中位数，单位 µs：

| 业务载荷 | net API p99 | RPC API p99 | net 计划起点总延迟 p99 | RPC 计划起点总延迟 p99 |
| --- | --- | --- | --- | --- |
| 64 B | 12.295 | 15.428 | 16.442 | 21.551 |
| 4 KiB | 14.838 | 31.124 | 19.142 | 43.092 |

每秒 1,000,000 次的 64 B RPC 三轮共拒绝 22,695 / 90,000 次（25.2%），没有发生器丢弃；不能称为零错误百万吞吐。
4 KiB RPC 同速率共拒绝 60,134 次、发生器丢弃 252 次。每秒 20,000 次的四组对照均出现超过 100 µs 的调度迟到，
突发场景也没有全部稳定通过；这些数据保留诊断，不作为相应负载的验收证据。原因尚未通过采样定位。

缓存实验在每轮交替 system / recycling 顺序。另用插桩二进制运行 30 种配置各一轮，每轮预热 2,000 次、正式 10,000 次：
64 B 单在飞无截止时，RPC 的 `new/new[]` 次数由 15 降到 9 次/调用；50 ms 截止时由 17 降到 10 次。
计数包含公共驱动，不覆盖直接 `malloc`、对齐分配或 RSS；插桩轮的延迟不用于性能结论。
未插桩的 64 B 单在飞 p99 仅从 4.715 变为 4.710 µs；8 个在飞由 11.617 变为 12.935 µs。
64 个在飞且带 50 ms 截止时由 77.805 变为 98.158 µs，五轮配对均变慢。因此缓存仅保留为显式实验选项。

`getrusage` 的 64 B 单在飞用户态 CPU 中位数为 net 822 ns/调用、RPC 1,742 ns/调用，内核态分别约 2,586 / 2,529 ns。
独立 `strace -c` 诊断包含各 1,000 次预热、10,000 次正式调用及启动/关闭：net / RPC 的 `sendto` 为 22,000 / 22,002，
`recvfrom` 为 44,001 / 44,007（其中 22,001 / 22,004 次返回错误；汇总不记录 errno），`epoll_pwait2` 为 22,001 / 22,003。
本次单在飞追踪未见额外的逐调用系统调用；新增成本主要在用户态是当前线索，但没有 perf 采样，不能归因到具体热点。
追踪运行的延迟不混入上表。

Release 和 ASan/UBSan/LSan 的现有测试均为 5/5 通过；基准另通过 13 个 sanitizer 自检场景，覆盖正常、发生器丢弃、拒绝和超时。
分配失败注入验证了异常后的关闭与异步排空。脚本独立重算逐请求 CSV 的分类计数、时间顺序与分位数，正式测量均通过校验。

复现使用 [基准说明](../README.md) 的构建命令与 `run_suite.py`：闭环/缓存为 `--suite cache --rounds 5 --iterations 100000 --warmup 5000`，
开放负载为 `--suite open --rounds 3 --iterations 30000 --warmup 5000`；分配诊断改用 `bench-alloc` 二进制，
加 `--suite cache --rounds 1 --iterations 10000 --warmup 2000`。各次使用独立输出目录及 `--cpu 2`。
