# lrpc v2 一元引擎

`lrpc::v2`（`v2/`）是在 net 之上重写的一元 RPC 引擎，与 v1 使用同一线协议：v2 客户端可以调用 v1 服务端，反之亦然（`v2_interop_tests`）。

## 结构

- **shard**：每个 `io_context` 一份。分级 slab（64 B–64 KiB，按需取块、空闲块按类限量缓存），1 ms 时间轮和它唯一的 `steady_timer`（惰性撤销），跨线程取消用的 stop hook 池。
- **connection**：客户端和服务端共用。读协程在一个固定窗口里就地解析帧，放不下的大帧临时换大缓冲；写协程把一轮里提交的帧从连续的发送块链一次写出。发送积压超过高水位时服务端暂停读。
- **client**：`unary_call` 是等待者本身，调用的全部状态住在等待方协程帧里；请求直接编码进发送缓冲；方法首次调用时驻留，之后只发编号。
- **server**：调用对象池化；handler 在读协程里就地启动；准入按方法声明的响应上限记账，不预占物理内存。

## 用法

```cpp
rpc::v2::shard shard{context};
rpc::v2::server server{shard, {{"demo/Echo", &handler, 4096}}};
auto const endpoint = server.listen({net::ip::address_v4::loopback(), 0});
rpc::v2::client client{shard};

// 在 shard 线程的协程里：
CO2_AWAIT_SET(connected, client.connect(endpoint));
echo = client.bind("demo/Echo"); // 一次字符串查找
CO2_AWAIT_SET(result, client.call(echo, request, response, &spec)); // result.code、result.size
```

`spec`（截止、相对超时、metadata）可省略；取消来自等待方的 stop token，可以从任意线程发出。

## 实测

同线程回环，epoll，CPU 钉在一个核上，5 轮交错取中位数（`benchmarks/unary_bench --transport net|rpc|v2`）：

| 场景 | 裸 net | v1 | v2 |
| --- | --- | --- | --- |
| 64 B，1 在飞，p50 | 3.26 µs | 4.11 µs | 3.42 µs |
| 64 B，1 在飞，用户态 CPU/调用 | 920 ns | 1692 ns | 1209 ns |
| 64 B，64 在飞，吞吐 | 3.20 M/s | 0.99 M/s | 2.82 M/s |
| 64 B，64 在飞，p50 | 14.7 µs | 56.1 µs | 16.2 µs |
| 4 KiB，1 在飞，p50 | 3.58 µs | 4.68 µs | 3.95 µs |
| 4 KiB，64 在飞，吞吐 | 1.04 M/s | 0.52 M/s | 0.87 M/s |
| 峰值 RSS | 5.8 MB | 29.9 MB | 5.9 MB |

`v2_gate_tests` 把客户端和服务端放在两个线程上，稳态下逐项断言：

- 每次调用两端都是 0 次堆分配，带不带截止都一样；
- 不带截止时 0 次时钟读取，带截止时每端 1 次；
- 64 在飞时两端都是每 64 次调用 1 次写。

## 尚未覆盖

- 只有一元调用：没有流式、压缩和响应 metadata（END 只带状态码和消息体）。
- 一个 client 对应一条连接，没有重连、负载均衡和重试。
- `server_context` 的 stop token 不能在 handler 结束后保留：未被请求过的停止状态会给后续调用复用。
